# 国际象棋模块设计

本模块是 `chinese-chess/` 的**姊妹模块**：同一套分层、同一套工程约束（纯静态、无构建、
无依赖），但棋种不同，规则层与引擎层全部重写。凡是「照搬」的地方，下面都会写明照搬的是
哪一条经验、为什么它可以照搬 —— 照着 `chinese-chess/docs/design.md` 一起读。

> 术语：本文里「象棋」= `chinese-chess` 模块（中国象棋），「国象」= 本模块（国际象棋）。
> 代码里的类名前缀统一用 `chess-`，localStorage key 用 `chess:...`，
> 与 `xq-`（象棋）互不冲突（AGENTS.md 的模块隔离要求）。

---

## 1. 目标与非目标

### 1.1 目标

1. 浏览器里单机下国际象棋，纯静态 HTML + CSS + JS，无构建工具、无框架、无第三方依赖。
2. 规则完整：易位（含路径不被攻击）、吃过路兵、兵升变、王车易位权、50 步和棋、
   三次重复、子力不足和棋、将死与**逼和（stalemate）**。
3. 四挡 AI（入门 / 初级 / 中级 / 高级），挡位是一张声明式策略表 —— 能写多强写多强，
   但「弱挡位像新手」比「高挡位绝对强」更重要（照搬象棋的判断）。
4. 内置残局库（分类可浏览）+ **谱载解法**：一部分残局带一条离线用 Stockfish 算出来、
   再用本模块规则层逐步复核过的正解线；AI 在这些局里按谱应着。
5. 中文记谱显示（棋子用「王后车象马兵」）+ 通用 **SAN** 记谱，着法列表可点击回看。
6. 对局操作：悔棋 / 重做 / 翻转 / **单步回看（上一步 / 下一步）** / 重开。
7. 提示：用当前挡位给一步建议；有谱载解法时优先给谱上正解。
8. 局面进出：复制 FEN、分享链接（点开就是同一局面）、自定义局面（存/改名/删）。
9. 深色模式跟随全站，不需要额外适配代码（本模块能用 `../global.css`）。

### 1.2 非目标（明确不做）

| 不做 | 原因 |
|------|------|
| 联网对弈、账号、排行榜 | 本仓库是静态站点，没有后端 |
| 浏览器里跑 Stockfish（wasm） | 体积、单线程限制、GPL 分发成本，见 `stockfish.md` §5；离线算解法用**原生** Stockfish |
| PGN 导入 / 导出整局 | 着法列表可复制成文本，够用；完整 PGN 涉及变例、注释、NAG，成本高收益低 |
| 变例树（在回看状态下走新着法**保留**原分支） | 与象棋一致：走新着法就截断后面的分支 |
| 引擎开局面库（opening book） | 没有权威且体积可接受的开局库；前几步慢一点可以接受 |
| 残局表库（Syzygy）打包进网页 | 3~5 子约 1GB、6 子约 150GB，见 `stockfish.md` §3 |

## 2. 与 chinese-chess 的关系：照搬 / 重写对照表

| 层 | 象棋模块 | 本模块 | 说明 |
|----|----------|--------|------|
| 常量 / 挡位表 | `config.js` | 重写 | 棋子编码、FEN 字符、挡位参数全不同 |
| 局面 / FEN | `position.js` | 重写 | 90 格 → 64 格；FEN 多了易位权与过路兵 |
| 规则 | `rules.js` | 重写 | 唯一「做错了会一直错」的一层，见 §5 |
| 记谱 | `notation.js` | 重写 | 中文纵线记谱 → SAN（消歧义规则复杂得多） |
| 对局状态机 | `game.js` | **照搬结构** | moves / cursor / 每步 FEN 快照 / 截断分支，一行逻辑都不用改 |
| 渲染 | `renderer.js` | 照搬结构，换几何 | 交叉点网格 → 8×8 格子（更简单），但「按格子 diff + mover 数组 + 补间」三条照搬 |
| 交互 | `interaction.js` | 照搬 | 点选 → 点目标 + 鼠标拖拽，逻辑与棋种无关 |
| 引擎 | `engine.js` / `worker.js` | 重写 | 评估与搜索重写；Worker 协议照搬 |
| 存档 / 分享 | `persist.js` / `share.js` | 照搬结构 | 只换 key、换 link 里编码的局面规模 |
| 残局库 / 解法 | `endgames.js` / `solutions.js` / `solution-book.js` | 照搬结构 | 数据结构与「必须带 ply 匹配」这条教训照搬 |
| 文档 / 工具 | `docs/*` / `tools/*` | 照搬结构 | 测试脚本形态一致（`node tools/test-*.mjs`） |

**一句话**：几何与规则全换，状态机与工程骨架照搬。所以工作量集中在 §5（规则）、§6（SAN）、
§7（引擎），其余都是「改名字改数据」。

## 3. 关键设计决策

### 3.1 局面表示：`Int8Array(64)` + 每步 FEN 快照

照搬象棋的选择（它否决了位棋盘、否决了对象数组），理由在这里同样成立，而且更省事：

- 64 格用一维数组，下标 `idx = rank * 8 + file`（`rank` 0 = 白方底线，`file` 0 = a 线）。
  棋子的「走法」用文件/横行的增量表达，边界判断用 `file`/`rank` 分量，不用哨兵。
- 局面是**可以 64 字节廉价拷贝的值**：置换表、终局判定、存档都变简单。
- 每步存一份 FEN 快照（约 60~70 字符），换来悔棋 / 回看跳转 O(1)。200 步约 14KB。
- **不做位棋盘**：分支因子比象棋大，但真正的瓶颈在 JS 搜索本身；位棋盘会把
  「着法生成」的代码量翻几倍，收益要到很高强度才显现。PST + 置换表是更划算的下一步。

### 3.2 渲染：DOM + CSS（棋盘是「格子」，不是「交叉点」）

象棋那边棋盘是 9×10 个**交叉点**，十字线用格子伪元素拼出来、还要单独处理河界断口。
国象反过来更简单：**64 个格子本身就是答案**，只需要

- 深浅格：`.chess-cell--dark` / `--light`，颜色走 CSS 变量（深色主题自动生效）；
- 每条边上的坐标（`a-h` / `1-8`）：照搬象棋「纵线号放在棋盘外」的做法
  （棋盘留 margin，`.chess-files` / `.chess-ranks` 用负偏移站进去；见象棋 §10.6 的三个坑）；
- 棋子绝对定位在格心（`left/top` 百分比），高亮用伪元素/外圈 —— 同象棋。

**颜色全部走 CSS 变量，不监听 `themechange`**：这是选 DOM 而非 Canvas 的直接收益（照搬）。

### 3.3 棋子用内联 SVG，不用 Unicode 字形

看着 Unicode ♔♕♖♗♘♙ 最省事，但踩过两个坑：

1. **U+265F 会被渲染成 emoji**（黑兵在某些平台带 emoji 变体），一盘子混着彩色 emoji 和字形；
2. 深浅主题下「白棋子的描边」没法统一 —— 白色棋子放在浅色格子上会糊成一片，
   而 Unicode 字形只能整体 `color`，描不了边。

所以：**棋子是一小段内联 SVG**（6 种形状各一份，作为字符串常量放在 `renderer.js` 的
`PIECE_ART` 里），白棋用「浅填充 + 深描边」、黑棋用「深填充 + 浅描边」，
两套主题各调一次 `--chess-p-fill` / `--chess-p-stroke` 即可。
不用 `<symbol>` / `<use>`，也没有图片文件、不引图标库、不联网。

形状是**简笔几何形**，不是写实雕刻 —— 一格才 60px 上下，细节多了只会糊成一团。
让六种互相分得开的三条规矩（每种的口鼻/耳朵、底座宽度、以及**十字只给王**）记在
`renderer.js` 的注释里。其中 **「十字只给王」是缩到棋盘尺寸后才发现的**：
原来「象 = 尖顶 + 十字」，跟「王 = 冠 + 十字」在一格大小上几乎一样，
所以象改成了尖顶帽 + 顶上小球。马的眼睛、象帽子的斜缝这两个**反色笔触**走
`chess-piece-ink` / `chess-piece-ink-line` 两个类 —— 它们必须比 `svg *` 那条统一着色规则更具体。

### 3.4 规则层自己写，但用公认 perft 钉住

象棋那边文档写了「perft 基准值来源不一、不敢用」，只能逐条断言规则点。**国象没有这个问题**：
从初始局面的 perft 是公认的（照抄 Chess Programming Wiki）：

| 深度 | 节点数 | 备注 |
|------|--------|------|
| 1 | 20 | |
| 2 | 400 | |
| 3 | 8 902 | |
| 4 | 197 281 | |
| 5 | 4 865 609 | 默认跑到这里（JS 秒级） |
| 6 | 119 060 324 | 可选，几十秒；CI 里默认跳过 |

再加上四个经典测试局面（都取自 CPW，其中 **Kiwipete 是必须的** —— 它专门覆盖易位、
被将时的解法、过路兵）：

| 名字 | perft(1..4) |
|------|-------------|
| Kiwipete | 48 / 2 039 / 97 862 / 4 085 603 |
| Position 3 | 14 / 191 / 2 812 / 43 238 |
| Position 4 | 6 / 264 / 9 467 / 422 333 |
| Position 5 | 44 / 1 486 / 62 379 / 2 103 487 |

**逐条断言 + perft 两层都要有**：perft 只报「总数不对」，逐条断言才能指出
「是吃过路兵错了还是易位错了」（象棋那边这条经验是当场赚回成本的）。

### 3.5 引擎自己写，不引 wasm

用户要的是「陪练型 AI，能写多强写多强」。Stockfish 的 wasm 版能在浏览器跑，但对本模块是负收益：

- 官方不发 wasm 构建（要依赖社区构建或自己 emscripten 编）；
- NNUE 权重 5~40MB，首屏很重；
- **多线程版在 GitHub Pages 上跑不起来**（要 `SharedArrayBuffer` → 要 COOP/COEP 响应头，
  Pages 不能自定义响应头）→ 只能单线程，棋力打一档；
- GPLv3 分发义务。

结论：网页里用自研引擎；**Stockfish 只在离线用**（原生二进制）算残局解法。
完整讨论与「将来若真要 wasm 的路线」记在 `stockfish.md` §5。

### 3.6 残局：内置库 + 谱载解法，全部离线生成

照搬象棋的整套机制：

- `endgames.js`：`{ id, name, fen, result, difficulty, source, note }`，
  按类别分页签（例：基础杀法 / 兵类残局 / 车类残局 / 战术题）。
- `solutions.js`（生成物）：一部分局面带一条**已证明的解法线**（`[{ move, san, fenAfter }]`），
  由离线脚本 `tools/gen-solutions.mjs` 用 Stockfish + Syzygy 表库算出来。
- `solution-book.js`：匹配解法时**必须带「已经走到第几手」**，不能只用局面 ——
  杀线里重复局面是常态（象棋那边踩过这个坑，写在它的 design.md 里）。
- 入库前用 `tools/verify-endgames.mjs` 复核：FEN 合法、轮走方有合法着法、解法线每一步
  都能通过本模块的规则层走通。

「哪些局面算合格」比象棋宽松：国象的残局结论（胜/和）可以用 **Syzygy 表库**给出
**可证明**的答案（DTZ/DTM），不必靠搜索猜。这一点用在两处：
填 `result` 字段，以及给解法线标注「唯一着法 / 最佳着法」。

### 3.7 记谱用 SAN

象棋用中文纵线记谱（`炮二平五`），国象这边**着法列表用 SAN**（`Nf3` / `exd5` / `O-O` /
`e8=Q+` / `R1e2`）。理由：SAN 是通用格式，复制出去能贴进任何棋谱软件；
界面文案（按钮、状态行）仍然是中文，棋子名显示「王后车象马兵」。

代价是 SAN 的生成规则比象棋记谱绕（消歧义三段式 + 升变 + 将军/将死后缀），
但它是**纯函数、可穷举测试**的一层，风险可控。

### 3.8 重绘与动画：照搬象棋那三条经验

象棋那边刚踩完的三个坑，本模块直接照搬结论：

1. **重绘按格子 diff，不重建**：同一格还是同一个子就留着那个元素。
   元素的 `left/top` 在插入之前设好 → 不会被过渡影响；反过来，全量重建会把
   正在做过渡的元素删掉重建，过渡作废。**尤其是「同一个任务里连着两次 draw」**
   （玩家走完一步、AI 那步同步落下）时必须靠 diff 才不会互相打断。
2. **AI 的应手排在补间后面**：`requestAiMove()` 发现棋子还在滑就先等
   （`renderer.afterAnimation`），滑完再派发；等待期间照样占住 `busy`。
3. **只有相邻一两步才做补间**：走子 / 悔棋 / 重做 / 单步回看动画，
   跨多步跳转直接落位（要么整盘棋子一起飞、要么逐步回放等几秒，两种都读不出来）。

## 4. 核心数据模型

### 4.1 坐标与编码

- 8×8 棋盘，`file` 0..7（a..h，向左到右）、`rank` 0..7（白方底线到黑方底线），
  `idx = rank * 8 + file`。
- 白方在 `rank` 0/1，黑方在 `rank` 6/7；白先。
- 棋子编码（`Int8Array(64)` 的元素）：`0` 空，正数白方，负数黑方，绝对值表种类：

  | 值 | 1 | 2 | 3 | 4 | 5 | 6 |
  |----|---|---|---|---|---|---|
  | 棋子 | 兵 P | 马 N | 象 B | 车 R | 后 Q | 王 K |

  判色用 `Math.sign(v)`，判种类用 `Math.abs(v)`（和象棋一致）。

### 4.2 局面对象

```js
{
  cells: Int8Array(64),   // 棋子
  side: 1 | -1,           // 轮走方（1 = 白）
  castling: number,       // 位掩码：1 白短易位 2 白长 4 黑短 8 黑长
  ep: number,             // 过路兵目标格下标，-1 表示没有
  halfmove: number,       // 50 步规则计数（半步）
  fullmove: number,       // 回合数（黑方走完 +1）
}
```

**易位权与过路兵必须进局面对象**：它们不是「能用着法推导出来的」状态 ——
车没动过但权已经丢了（王动过一次）、上一手是两格兵走才能吃过路兵。
FEN 里这两项一丢，三次重复判定和存档恢复都会错。

### 4.3 FEN / EPD

- 解析 `position.js` 的 `parseFen`：6 段（棋子布局 / 轮走方 / 易位权 / 过路兵目标 /
  半步计数 / 回合数）。缺后两段时按 0 / 1 补（很多手写 FEN 只写四段）。
- 输出 `toFen` 必须与解析**互逆**，并且**规范化**（用于「框里就是当前局面」的判等，
  照搬象棋的 `validateFreeFen` 顺带规范化的做法）。
- 重复局面判定用「前四段 + 轮走方的简化签名」（`positionSignature`），不含步数计数。

### 4.4 Zobrist 与重复判定

- Zobrist 表：`[64 格][12 种（色 × 种类）]` + `轮走方` + `易位权（16 种组合）` + `过路兵文件（8）`，
  用固定种子生成（自己写一个 xorshift，避免 `Math.random` 导致跨会话哈希不一致）。
- 增量维护（走子/回退时异或），**回退必须能把哈希还原**（引擎靠这个）。
- 三次重复只看**当前这条线**（起始局面 + `moves[0..cursor)`），不看被截断的分支。

## 5. 规则层（`js/rules.js`）—— 全模块风险最高的一层

### 5.1 着法编码

照搬象棋的做法：一个着法是一个整数，不建对象（搜索里每层要生成几十个着法，
对象会带来 GC 压力）。位布局：

```
bit  0-5   from（0..63）
bit  6-11  to（0..63）
bit 12-14  升变种类（0 = 不升变，否则 2..5 = N/B/R/Q）
bit 15-16  标记：0 普通 / 1 吃过路兵 / 2 易位 / 3 双步前进（只在内部用）
```

配 `encodeMove(from, to, promo, flag)` / `moveFrom` / `moveTo` / `movePromo` / `moveFlag`，
与象棋的 `encodeMove` / `moveFrom` / `moveTo` 同名 —— 上层（`game.js` / `main.js`）的代码
才能几乎照搬。

### 5.2 生成与合法性

分两层，**不要合成一层**：

- `generateMoves(pos)`：**伪合法**着法（把对方的王当成可以吃的普通棋子）。快、无副作用。
- `generateLegalMoves(pos)`：对每个伪合法着法「走一步 → 检查自己的王是否被攻击 → 退回来」。
  被将军时这自然只剩解将的着法（不需要单独写「应将」逻辑）。

攻击判定单独成函数 `isAttacked(cells, idx, bySide)`：四条射线（车/后）、四条斜线（象/后）、
八个马位、两个吃子方向的兵、王的邻格。易位额外查**王经过的两格**（含起点）不被攻击。

> **吃掉对方的王是禁止的**：伪合法生成里可以出现，但 `generateLegalMoves` 之后不会留；
> 终局判定靠「无合法着法 + 是否被将军」而不是「王被吃了」。

### 5.3 特殊着法

| 着法 | 要点 |
|------|------|
| 易位 | 王两格、车越过；条件：易位权在、中间完全空、王**起点与经过格**都不被攻击（终点由合法性检查覆盖） |
| 吃过路兵 | 目标格是空格，被吃的兵在「目标格的同 rank、我方兵的原 file」上 |
| 升变 | 兵到末 rank 时必须选（生成 4 个着法：N/B/R/Q）；`halfmove` 归零 |

### 5.4 终局判定（`gameStatus(pos)`）

顺序很重要（先判无着法，再判计数类）：

1. 无合法着法 → 被将军 = `checkmate`，否则 = `stalemate`（逼和，**象棋没有这一条**）；
2. `halfmove >= 100` → `fifty`（50 步和棋）；
3. 子力不足（`insufficient`）：K vs K、K+单马/单象 vs K、K+B vs K+B 且两象同色格；
4. 三次重复（`repetition`）—— 需要**整条着法线**，所以判定放在 `game.js` 而不是 `rules.js`。

## 6. 记谱（`js/notation.js`）

### 6.1 SAN 生成

`toSan(pos, move)` 在**走这一步之前**的局面下计算（和象棋一样：记谱必须在改棋盘之前算）：

1. 易位 → `O-O` / `O-O-O`；
2. 棋子字母：`K Q R B N`，兵不带字母；
3. 吃子 → `x`（兵吃子写 `exd5`，吃过路兵写成普通吃子形态 `exd6`）；
4. 消歧义（**三段式，顺序不能变**）：
   - 同类棋子有多个能到这个目标格 → 加起始**纵线**（`Nbd2`）；
   - 起始纵线也一样（同 file 有两只）→ 改加起始**横行**（`R1e2`）；
   - 还分不清（三只以上同 file 不同的 rank？）→ 纵线 + 横行都写（`Qh4e1`）；
   - 判据是「**其它同类棋子能否合法走到同一目标格**」，不是「有没有同类棋子」——
     被牵制的棋子不算（这点错了在实战里很难发现）。
5. 升变 → `e8=Q`（升变后将军就 `e8=Q+`）；
6. 后缀：走完发现对方被将军 → `+`，被将死 → `#`。

### 6.2 显示与保存

- `moves[i]` 里存 `{ move, san, captured, fenAfter }`（照搬象棋的字段含义）。
- 着法列表按回合成对显示（`1. e4 e5  2. Nf3 ...`，白黑各一列）。
- 界面文案中文；棋子名映射 `K→王 N→马 B→象 R→车 Q→后 P→兵`，只在「升变选择」这类
  需要人类读的地方用到。
- **不做 SAN 解析**（不从文本读棋谱）；自定义局面走 FEN。

## 7. 引擎（`js/engine.js` + `js/worker.js`）

### 7.1 评估：只做 O(1) 查表

照搬象棋那条硬规矩：**评估在叶节点被调用上百万次，任何需要「生成着法」的项都不能加**
（机动性、王安全这种漂亮指标都先放）。国象这边能纯查表拿到的、性价比最高的几项：

| 项 | 说明 |
|----|------|
| 子力 | `P100 N320 B330 R500 Q900`，王记 0 |
| 位置表（PST） | 每种棋子两张（中局 / 残局），按兵/马/象/车/后/王共 12 张表，**镜像复用**（黑方用横向镜像） |
| 相位插值 | 由剩余子力算 0..256 的相位，中局表与残局表线性插值（王在残局该上前、中局该躲角落，靠这个自然得到） |
| 双象加成 | 一方有双象 +30（很小的常量，别喧宾夺主） |
| 兵结构 | 叠兵 / 孤兵 / 通路兵，各给一个小常量；通路兵按推进程度递增加分 |

### 7.2 搜索

从象棋那套搬过来的部分，和国象特有的部分：

| 机制 | 说明 |
|------|------|
| negamax + alpha-beta + 迭代加深 | 顶层按时间截断（照搬：`timeLimitMs` 是真正的闸门，`depth` 只是上限） |
| PVS | 第一个着法全窗口，其余零窗口；省时间很直接 |
| 置换表 | Zobrist 键 → 深度 / 边界标志 / 分数 / 最佳着法；同象棋的替换策略 |
| 着法排序 | TT 着法 → 吃子按 MVV-LVA → 杀手着法 → 历史启发表 |
| 静态搜索 | 只搜吃子 + 升变；**弱挡位关掉它**（象棋那条「关掉静态搜索最像新手」的经验直接可用） |
| 将军延伸 | 被将军的节点不消耗深度（上限沿用挡位参数） |
| 空着裁剪 | 限深度、且**只在非残局**用（残局里 zugzwang 会让空着裁剪给出错误结论） |
| 重复 / 50 步 | 搜索中遇到就当和棋（返回 0），否则引擎会主动走进「重复三次」的坑 |

**超时必须用异常中断，所以 searcher 的棋盘要能回滚**（象棋那边踩过的坑：异常从
`make` / `unmake` 中间穿过去，棋盘停在「走了一半」的状态）。做法照搬：`make/unmake`
成对，`try/catch` 里恢复。

### 7.3 挡位表（`config.js` 的 `LEVELS`）

声明式，四个挡位，每个是一组参数：

```js
{ id: 'novice', name: '入门', depth: 1,  timeLimitMs: 200,  quiescence: false, noise: 120, blunderRate: 0.35 }
```

- **弱挡位像新手比高挡位强更重要**：`quiescence: false` + `noise` + `blunderRate` 是主力
  （象棋那边验证过：关掉静态搜索的 AI 会「兑子到一半以为占了便宜」，这正是初学者的特征）。
- 高挡位：`depth` 放宽、`timeLimitMs` 1200~1500ms、`noise/blunderRate` 归零。
- 可选加强项（二期）：把「离顶端几步内是杀棋」的探测做成开关，用来解排局（对应象棋的
  `probeMate`）。

### 7.4 Worker 协议

照搬象棋的形态（主线程与引擎之间只过这一个协议，两边不互相 import）：

```
主线程 → Worker：{ type: 'search', id, fen, level }
Worker → 主线程：{ id, move: { from, to, promo } | null, nodes, ms }
              或 { id, type: 'error', message }
```

**不返回 SAN**：主线程把着法记进对局状态时本来就要算一次 SAN（玩家自己走的也要算），
Worker 再算一遍是重复劳动（这条也是照搬象棋的结论）。

## 8. 渲染与交互

### 8.1 棋盘与坐标

- `.chess-board`：`display: grid` + `8×8` + `aspect-ratio: 1`，64 个格子是 `<button>`（键盘可遍历）。
- 深浅格：`.chess-cell--dark` / `--light`，颜色走 CSS 变量（两套主题各一组）。
- 坐标：底部 `a-h`、左侧 `1-8`。**照搬象棋「纵线号放在棋盘外」的做法**：棋盘上下/左右留
  margin，坐标行/列用负偏移站进去 —— 那边踩过的坑（半格边距被棋子占满、数字被压住）在这里
  同样存在。
- 翻转（`setFlipped`）：整块棋盘 `rotate(180deg)`，棋子与坐标文字各自反向转回来；
  动画那 0.3 秒里把坐标文字藏起来（照搬象棋的 `is-flipping`）。坐标是文字，转起来比棋子刺眼。

### 8.2 高亮

象棋给「轮走方的全部棋子」加了一圈紫环 —— 国象不能照抄：棋子是 SVG，
`outline` 会画成一个矩形框。所以国象的高亮清单是：

| 状态 | 画在哪 |
|------|--------|
| 上一步的起点 / 终点 | 格子底色（半透明强调色） |
| 选中 | 格子底色（更实一档） |
| 可走的空格 | 格心小圆点 |
| 可吃的子 | 目标棋子外的**圆形**描边（用 SVG 外层的一个圆形元素，不是 outline） |
| 被将军的王 | 王的格子底色走危险色 + 王外一圈危险色圆环 |
| 轮到谁走 | 只体现在棋盘上方的状态行（方名着色），不标满盘棋子 |

### 8.3 升变选择

兵走到末 rank 时弹一个**小浮层**（4 个按钮：后 / 车 / 象 / 马，各画对应的 SVG），
选中后才真正落子；`Esc` 取消等于没走。

- 用原生 `<dialog>` + `showModal()`（照搬象棋的结论：Esc 关闭、焦点陷阱都是白送的），
  或者棋盘内定位的小面板 —— 实现时挑一个，别手写遮罩层。
- 键盘：方向键/数字键选中，回车确认。

### 8.4 交互

- **点击选子 → 点击目标**（主路径，触屏也走这条）；**鼠标可以拖拽**（`pointerType === 'mouse'`），
  拖拽不做残影（照搬象棋）。
- 目标格不在合法着法集合里 → 视为「改选另一个子」，不报错、不弹窗。
- 键盘：格子是 `<button>`（Tab 可遍历）、`Esc` 取消选中、`H` 提示、`F` 翻转、`?` 说明、
  `Ctrl+Z` 悔棋。**`←` / `→` 单步回看**（比象棋多这一对，因为着法列表上方就有这两个按钮）。

## 9. 残局库与谱载解法

### 9.1 数据结构（照搬象棋的字段形状）

```js
// endgames.js
{ id, category, name, fen, result, difficulty, source, note }
// result: 'white' | 'black' | 'draw'  —— 用 Syzygy 或 Stockfish 深搜得出，不是猜的
// difficulty: 1..5（几手杀 / 唯一着法数 / 表库步数）
```

分类（页签）先定四类，数量先做 30~60 局，跑通流程比堆量重要：

| 页签 | 内容举例 |
|------|----------|
| 基础杀法 | KQ vs K、KR vs K、双象杀、马象杀 |
| 兵类残局 | K+P vs K 的关键格、KP vs KP |
| 车兵类 | 卢塞纳局面、菲力多尔局面 |
| 战术题 | 一步杀 / 两步杀、牵制与双击（`result` 仍由引擎确认） |

### 9.2 谱载解法（生成物）

```js
// solutions.js —— 由 tools/gen-solutions.mjs 生成，不要手改
{ [endgameId]: [ { san, move, fenAfter }, ... ] }
```

`solution-book.js` 把它编成 `Map`，键是 **`endgameId + '|' + ply`**。
匹配必须带 ply：残局解法的杀线里重复局面是常态，只用局面匹配会给出错的那一步
（象棋那边踩过这个坑，写在它的 design.md 里）。

### 9.3 离线流水线

```
公开棋谱 / 教材局面 ─┐
chessdb 统计页的    ├→ 候选 FEN → gen-solutions.mjs（原生 Stockfish + Syzygy）
「最长局面」等素材 ─┘        │
                             ├→ solutions.js（正解线）
                             └→ result / difficulty 回填 endgames.js
                                        │
                                        ▼
                            verify-endgames.mjs（用本模块规则层逐步复核）
```

命令与参数见 `stockfish.md`。「来源」字段一律写清（哪个谱/哪个站点/哪本书），
不要把别人的数据当自己的。

## 10. 持久化与分享

- localStorage key：**`chess:state`**（必须带模块前缀，AGENTS.md 要求模块间不共享 key）。
- 存的内容：`level`、`playerSide`、`mode`、`initialFen`、`moves`、`cursor`、`twoPlayer`、`endgameId`。
  局面本身一律走 FEN 快照，不另存易位权/过路兵（FEN 里已经有了）。
- 存盘时机：走子后、悔棋后、切挡位后（防抖 300ms），不在 AI 思考期间存。
- 分享链接（`share.js`）：把 FEN 编进 URL（`?fen=...`，`encodeURIComponent` 处理空格与斜杠），
  可选带 `endgameId` 与「从第几手开始」。打开链接时**优先于存档**，解析失败只在状态行提示一句。
- 存档容错：任何字段不合法 → 整体重建为标准开局（照搬象棋 persist.js 的容错策略）。

### 11.1 布局（照搬象棋的网格）

```
├──────────────────────────────────────┤  （可点击跳转，      │
│ 悔棋/重做/重开/翻转/提示/复制FEN/链接 │   超出面板自己滚）   │
└──────────────────────────────────────┴─────────────────────┘
```

- 桌面用显式 `grid-area`（棋盘列 + 300px 侧栏）；窄屏（≤860px）单列。
- **工具栏在棋盘列内部**，不单独占一个网格行。网格行的位置由更高的那一列决定：
  工具栏另起一行的话，着法列表一长就会被顶到列表下面去（棋盘和工具栏之间空一大块）。
  真正的约束是「**侧栏不能比棋盘列高**」，由 `着法` 面板的 `max-height` 保证
  （棋盘列的高度是定值：棋盘自身 max-width 560px + 状态行 + 工具栏）。
- 状态行在棋盘**正上方**（象棋的理由同样成立：窄屏下侧栏会被挤到最下面）。
- 着法面板标题行是三列网格：左「着法」、中「上一步 / 下一步」、右「复制」。

## 12. 测试策略

全部用 Node 直接跑，不需要浏览器、不需要装依赖（与象棋一致）：

| 命令 | 作用 |
|------|------|
| `node chess/tools/test-rules.mjs` | perft（默认 1~5，`--deep` 加 6）+ 逐条规则点断言 |
| `node chess/tools/test-notation.mjs` | SAN 生成（消歧义、升变、将军/将死后缀） |
| `node chess/tools/test-game.mjs` | 对局状态机：悔棋、回看跳转、截断、存档容错 |
| `node chess/tools/test-engine.mjs` | 引擎：增量哈希与全量一致、回退还原、唯一着法局面、开关对照组 |
| `node chess/tools/verify-endgames.mjs` | 残局库：FEN 合法、有合法着法、解法线逐步可走 |
| `node chess/tools/selfplay.mjs` | 自对弈冒烟：管「状态组合」，单测覆盖不到（象棋那边靠它抓到过两个真 bug） |

两类测试的分工照搬象棋：**单测钉稳定的东西**（纯函数性质、唯一正确着法、只翻一个参数的
对照组），**冒烟管组合**（几百手真实对局里才会出现的状态）。perft 是国象的额外福利：
规则层有一个绝对权威的判据。

## 13. 已知限制（写进实现时的注释，不要偷偷「以后再说」）

1. **引擎棋力有上限**：自研 JS 引擎，不是 Stockfish 级；高挡位目标「下得过业余爱好者」，
   不承诺对强引擎/高段位。
2. 没有开局库：前几步靠搜索，慢一点、变化少一点。
3. 没有在线表库：残局结论只覆盖内置库 + 离线算过的解法。
4. 不做 PGN 导入导出、不做棋钟、不做变例树。
5. 锦标赛细则（如「三次重复必须由一方提出」）不做：本模块自动判和。
6. 移动端不做拖拽（触屏走「点选 → 点目标」），与象棋一致。
