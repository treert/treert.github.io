# 国际象棋（网页单机版）

浏览器里对弈国际象棋。纯静态 HTML + CSS + JS，无构建工具、无框架、无第三方依赖。
四个挡位的自研 AI（跑在 Worker 里，不卡界面）、**SAN 记谱**、复盘跳转、悔棋重做、
单步回看、翻转、提示、深色模式，外加一个**局面库**：内置 25 局残局（四页），
还可以把你下到一半的局面存下来，或者粘贴外部 FEN 导进来。

**规则是完整的**：易位（含「王经过的两格不被攻击」）、吃过路兵、升变、
50 步、三次重复、子力不足、将死与**逼和**。规则层用公认的 perft 基准值钉死
（初始局面 1~5 手 + Kiwipete 等四个局面），这是本模块唯一绝对权威的判据。

**局面也能拿出去**：复制 FEN 给别的软件，或者复制一条**分享链接** ——
别人点开就是那个局面。**棋谱也能拿出去**：「着法」面板标题右边点一下，
复制成一段文本（一行一个回合）。

**一部分残局能「按谱走」**：库里 7 局带有一条**已证明的杀线**（用内置的精确强制杀
搜索算出来、再用本模块规则层逐手校验过）。这样的局会在棋盘上方标出「有解法（N 步杀）」，
「提示」直接给谱上的正解（状态行写「谱载解法」），**AI 也按谱应着** ——
于是你能顺着那条线一直走到将死。走岔了自动回到引擎搜索。

**也可以不下 AI** —— 侧栏「对局」面板里有个**双人对弈**开关，
打开后黑白两边都由人来点（同一台设备上轮流走）。此时「执子」会禁用，
悔棋也只退一步。

## 本地运行

用了 ES Module，**不能直接双击 `index.html`**（`file://` 下会被 CORS 拦掉），
Worker 也需要 HTTP 环境。起个静态服务即可：

```bash
cd treert.github.io
python -m http.server 8000
# 打开 http://127.0.0.1:8000/chess/
```

部署在 GitHub Pages 上是 HTTP 服务，不受影响。

## 架构

**分两层。** 对局层（`game.js`）是纯逻辑状态机，界面层只负责把它画出来、
把点击翻译成它的调用，自己不持有任何棋类规则。

**状态集中在 `main.js` 的 `app` 对象上。** 模块之间不互相 import，
统一通过 `app` 上的回调协作，避免依赖成网 —— 与 `chinese-chess`、`conway-life-game` 同一套做法。

**AI 跑在 Worker 里。** 主线程只发 `{ fen, level }`、收着法。搜索期间禁用操作
（最长 1.5 秒不可中断，见「已知限制」）。

**数据流**：点击格子 → `interaction.js` → `app.onCellClick` → `game.js` 校验并走子
→ `refresh()` → `renderer.draw()` → 若轮到 AI，`worker.postMessage` → 回来再走一步。

## 关键设计决策

每条都记下**否决了什么**，避免以后重复讨论。完整版在 [`docs/design.md`](./docs/design.md) §3。

### 1. 局面用 `Int8Array(64)` + 每步一份 FEN 快照

棋盘是 64 字节的 `Int8Array`，**拷贝一份就是一份局面** —— 走子、合法性探测、
搜索里的 make/unmake 全都靠它。对局状态里每走一步存一份 FEN 快照（约 50 字符），
换来悔棋与复盘跳转 O(1)；200 步也就 10KB。

### 2. 悔棋只移动游标，绝不删除着法

`moves` 数组一直保留，`cursor` 指向「当前在第几步」。所以重做是免费的，
只有在「回看状态下走新着法」时才截断后面的分支。
人机模式的「悔棋」会一直退到轮到你走（否则 AI 立刻又走一步，等于没悔）。

### 3. 用 DOM + CSS 渲染，棋子用**内联 SVG**，不用 Unicode 字形

- 颜色走 CSS 变量 → 深色模式自动生效，不需要监听 `themechange`
- 命中测试用事件委托，免费；格子是 `<button>`，键盘可遍历
- 64 格 + 32 子，DOM 性能完全够

**棋子必须是 SVG**：`♔`/`♟` 这类字形在移动端会被渲染成 emoji（尺寸、颜色都不受控），
而白棋在当前色系下会和浅格糊成一片 —— 字形只能整体 `color`，描不了边。

图形用的是 **Cburnett 棋子集**（作者 Colin M. L. Burnett），12 个 45×45 的 SVG
放在 `chess-icons/` 里（**保持原素材的样子**：能直接打开看、能跟下载下来的文件 diff）。
`js/piece-art.js` 在装配页面之前把它们读进来，运行时只做两件事：
取出 `<svg>` 里的标记、把两个色值换成 `--chess-p-fill` / `--chess-p-stroke`
（**路径数据一个字符都没改**）。这套图形是**黑白两套路径**（细节不同，比如马的鬃毛），
而颜色仍然只由那两个变量说了算 —— 深浅主题只换变量、不换图形。

> 不引图标库、不联网、也没有图片文件，但多了 12 个 SVG 文件，
> 于是**必须走 http**：`file://` 下 fetch 会被拦，棋盘会退化成占位圆圈（状态行会提示原因）。
> 署名与许可在 `chess-icons/README.md`。
> 更早那版是手写的「简笔几何形」，能认但难看 —— 换掉的理由见 `docs/design.md` §3.3。

**坐标放在棋盘外面**（棋盘留 margin，坐标行用负偏移站进去）——
象棋在同一个地方踩过坑（数字被棋子压住），照搬那个结论。

### 4. 规则层自己写，但用**公认的 perft** 钉死

国象有权威基准值（初始局面 20 / 400 / 8902 / 197281 / 4865609，Kiwipete 48 / 2039 / …），
所以规则层能自动验到底 —— 这是象棋那边没有的福利（那边只能逐条断言）。
perft 只报「总数不对」，所以**逐条断言也要写**：它能指出是哪条规则错了。
细节见 `tools/test-rules.mjs` 与 `docs/design.md` §3.4。

**合法性用「走一步 → 查自己的王是否被攻击 → 退回来」**，不自己推导
「被将军时哪些能走」—— 后者要枚举被牵制、双将、垫将的所有情况，写不对就静悄悄地错。

### 5. 引擎自己写，不引 Stockfish wasm

体积、GitHub Pages 上只能单线程、GPL 分发，三条加起来不值得；而且这个模块的定位是
「能陪人下完一盘」。将来要换 Stockfish 的路线与代价写在 [`docs/stockfish.md`](./docs/stockfish.md) §5。

评估**只做 O(1) 查表**（子力 + 位置表 + 兵形 + 象对），**不许出现需要生成着法的项** ——
评估在叶节点被调用上百万次，生成着法等于把搜索成本翻倍。

### 6. 关掉静态搜索是让 AI「像新手」最有效的单个开关

这是挡位设计的核心，有测试正面钉住（`tools/test-engine.mjs` 的对照组）：
关掉静态搜索的 AI 会在兑子序列中途停下、以为自己占了便宜，然后被吃回 ——
这正是初学者的真实特征，比单纯降深度像得多。所以「入门」和「初级」都关掉了它，
再叠上根节点评分噪声与「按概率故意走次优着」。

### 7. Worker 不返回 SAN

主线程把着法记进对局状态时**本来就要调一次记谱**（玩家自己走的棋也要记谱），
Worker 再算一遍是重复劳动，还让 Worker 多依赖一个模块。

### 8. 谱载解法的键必须带「第几手」

**杀线里重复局面是常态**：子力少时来回走、王来回躲，同一条线上会反复回到同一个局面。
只用局面签名当键，后一次会把前一次盖掉 —— 同一个局面拿到的是另一处该走的着法，
走错一步整条线就废了。所以键是 `endgameId + ply`，见 `solution-book.js`。

### 9. 测试分工：perft 是权威，单测钉稳定的，冒烟管组合

单测里**不出现「搜了多少节点 / 花了多少毫秒」**这类断言（随机器波动），
只钉三类稳定的东西：纯函数的数值性质、只有唯一正确着法的局面、以及**带对照组的开关**。
`tools/selfplay.mjs` 管的是**组合状态** —— 几百手真实对局里才会出现的局面
（吃过路兵的同时暴露王、易位权边角、升变后立刻被将军…），单测按构造覆盖不到。

## 局面库与谱载解法

内置 25 局，分成四页：

| 分类 | 局数 | 说明 |
|------|------|------|
| 基础杀法 | 9 | 单后 / 单车 / 双车 / 双象 / 马象…对单王，子力定式，适合入门 |
| 兵类残局 | 6 | 方格法则（兵能不能独力升变）、王护送兵、车兵被挡在角上 |
| 车兵类 | 5 | 车 + 通路兵、车对车 / 象 / 马的和棋定式 |
| 战术题 | 5 | 底线一步杀、贴身一步杀、闷杀、双车封排 |
| 自定义 | 0 起 | 你自己存下来的局面，见下一节 |

每局都带 `source`（`子力定式` / `方格法则` / `教材定式` / `构造题`）——
这 25 局是**手工构造的定式与构造题**，不是从某个数据库抄来的。

**7 局带一条已证明的杀线**（`js/solutions.js`，键就是局 id）。

标题右边的「局面库」按钮打开弹窗（按钮上会显示你现在在哪一局），
里面按页签分好类，点一局即可载入。载入后棋盘上方会显示这是哪一局、**已走几步**、
有没有解法；想回普通对局，点弹窗里的「退出残局」。

**页签下面有个过滤框**（按名字过滤，空白分隔的多个词是「与」）。三条约定：

- **只匹配名字，不匹配 FEN** —— 名字是列表上唯一显示的文本
- **只在当前页签内生效**，跨页签的线索交给**页签徽标**（有过滤词时徽标显示各页命中数）
- **Esc 是两级的**：先清过滤词，框空了之后再按才关弹窗

### 解法是离线生成的数据

| 命令 | 需要什么 |
|------|----------|
| `node chess/tools/gen-solutions.mjs local` | 不需要任何外部程序。内置**精确**强制杀搜索（攻方 ∃ / 守方 ∀），只证明短杀（默认 ≤ 5 个半层 = 3 步杀），跑出来的线一定对，但找不到长杀 |
| `node chess/tools/gen-solutions.mjs stockfish` | 需要本地装好 Stockfish（`STOCKFISH` 环境变量或默认路径），挂了 Syzygy 表库就是 DTZ 口径的可证明结论 |
| `node chess/tools/gen-solutions.mjs emit` | 把刚才算出来的结果写成 `js/solutions.js` |
| `node chess/tools/verify-endgames.mjs` | 入库闸门：FEN 合法、轮走方有合法着法、每条解法线**逐手用本模块规则层走通**、末局确实是将死 |

现在这份数据是 **local** 那条路生成的（`SOLUTIONS_SOURCE` 里记着）。
**没找到的局不编** —— 界面上就是「暂无谱载解法」，点「提示」回退本地引擎现算。
引擎与权重不进仓库：生成物是数据，**运行时不需要引擎、也不联网**。
怎么装 Stockfish、怎么手动验一局，见 [`docs/stockfish.md`](./docs/stockfish.md)。

## 自定义局面

局面库弹窗里有个 **「自定义」页签**（带条数徽标）。相关的入口按**动作的性质**分在三处：

| 想干什么 | 去哪 | 怎么做 |
|----------|------|--------|
| **挑一局来下** | 标题行左边「局面库」 | 选页签 → 点一局 |
| **把 FEN 框里那个局面收进库里** | 标题行右边「保存 / 导入」 | 起个名字 → 「存为自定义局面」。**框里打开时就是当前局面**，不动它就是存当前这盘棋 |
| **把 FEN 框里那个局面摆到棋盘上** | 标题行右边「保存 / 导入」 | 「载入到棋盘」。**不进库**，棋盘换成一个「临时局面」 |
| **把当前局面拿出去** | 工具栏「复制 FEN」/「复制链接」 | 点一下就复制（按钮会短暂显示「已复制」）。剪贴板不可用时会把内容填进「保存 / 导入」的框里，手动复制即可 |
| **把这盘棋的着法抄出来** | 侧栏「着法」面板标题右边「复制」 | 一行一个回合（`1. e4 e5 2. Nf3`） |
| **给存过的局面改名字 / 删掉** | 「局面库」→「自定义」页签 | 点那一行右边的 **✎** / **✕**（删之前会问一次） |

**「保存 / 导入」里只有一个 FEN 框**：打开时框里已经填好当前局面（并且是全选状态），
所以「存当前这盘棋」和「存别处的局面」是同一个动作 —— 不动它就是当前局面，
粘一段别处的 FEN 覆盖掉就换成了那个局面。**框里就是当前局面时「载入到棋盘」是灰的**；
**解析不了的 FEN 不禁用** —— 点了会告诉你哪儿不对，禁掉的话用户只知道按钮坏了。

**两道校验，松紧不同**：

| | 「载入到棋盘」 | 「存为自定义局面」 |
|---|---|---|
| FEN 能解析、局面合法 | 要 | 要 |
| 轮走方有合法着法 | **不查** —— 摆上去看看完全合理 | **要** —— 已经终局的局面没有练习价值 |

「轮走方正被将军」两道都不拦（那是合法局面，他应将就是了）。
存进库还要过名字那两道（非空、不超长）和去重（同一局面不重复存），
任何一道不过都会把**原因**显示在弹窗底部。

**自定义局面没有「结论」**：程序无从知道你存那个局面时的胜负，
界面上只显示「自定义局面」，不做「达成目标」判定。
存储位置是 localStorage 的 `chess:endgames`，**最多 100 条**；
对局本身存在 `chess:state`。清浏览器数据 / 换设备都会丢 —— 想长期保留就把 FEN 抄出来。

**分享链接只带局面**（`?fen=`），不带着法历史、挡位与执子方 ——
语义是「来看这个局面」，不是「来看我下的这盘棋」。**打开链接优先于存档**，
而且参数读完就立刻用 `history.replaceState` 抹掉：留着的话，之后每次刷新都会把你
从「自己后来选的局面」拽回分享的那个局面，看起来很像 bug。

## 常见改动

### 调整某个挡位的手感

改 `js/config.js` 的 `LEVELS`。参数含义：

| 参数 | 作用 |
|------|------|
| `depth` | 迭代加深的上限，实际由 `timeLimitMs` 截断 |
| `timeLimitMs` | 时间上限（毫秒） |
| `quiescence` | 是否做静态搜索。**关掉会让 AI 明显「像新手」** |
| `noise` | 根节点评分扰动幅度。越大越容易走次优着 |
| `blunderRate` | 按此概率故意走次优着（模拟看漏） |
| `checkExtension` | 将军延伸的层数上限 |

### 提升棋力

**评估方向**：改 `config.js` 的参数或 `engine.js` 的 `evaluate()`。
**不要加需要生成着法的项**（理由见上面第 5 条）。

**搜索方向**：`engine.js` 里的置换表、空着裁剪、静态搜索都可以加长。

### 加一局残局 / 加一条解法

```bash
# 1. 在 js/endgames.js 里按 { id, name, fen, result, difficulty, source, note } 加一条
#    （category 由注册表按页签自动补上，别写进数据里）
# 2. 入库闸门（会把不合法的局面连原因一起打出来，也会复核解法线）
node chess/tools/verify-endgames.mjs
# 3. 想给它配一条杀线：先生成、再写盘、再复核
node chess/tools/gen-solutions.mjs local
node chess/tools/gen-solutions.mjs emit
```

`verify-endgames.mjs` 不是走过场：它挡的是「FEN 抄错一个字符」「轮走方已经被将死」
「解法线走到一半走不通」这类靠肉眼看不出来的问题。

### 改棋盘样式

颜色在 `style.css` 顶部的 `--chess-*` 变量里（深浅两套只换变量）：
格色、格线、坐标、棋子（白/黑两套填充 + 描边）、五种高亮。
坐标的位置在 `renderer.js` 里（`a-h` / `1-8` 站在棋盘外面）。

## 工具与测试

全部用 Node 直接跑，**不需要浏览器、不需要装依赖**：

| 命令 | 作用 |
|------|------|
| `node chess/tools/test-position.mjs` | 局面层：FEN 往返、容错、Zobrist、重复签名 |
| `node chess/tools/test-rules.mjs [--deep]` | 规则层：**perft**（默认 1~5 手，`--deep` 加第 6 手）+ 逐条规则点断言 |
| `node chess/tools/test-notation.mjs` | SAN：消歧义、升变、将军/将死后缀、吃过路兵 |
| `node chess/tools/test-game.mjs` | 状态机：悔棋、回看跳转、截断、三次重复、存档容错 |
| `node chess/tools/test-engine.mjs` | 引擎：增量哈希与全量一致、全程回退后还原、唯一着法局面、开关对照组 |
| `node chess/tools/test-renderer.mjs` | 渲染层几何与 diff：格子顺序、棋子落点、补间是搬元素不是重建 |
| `node chess/tools/test-share.mjs` | 分享链接：编解码往返、坏链接不炸 |
| `node chess/tools/test-solution-book.mjs` | 谱载查表：逐步命中、走岔查不到、重复局面不串 |
| `node chess/tools/test-main.mjs` | 装配层端到端：替身 DOM + 进程内 Worker，把整页跑一遍 |
| `node chess/tools/selfplay.mjs [白挡位] [黑挡位] [上限]` | 自对弈冒烟：不崩、不超时、着法全合法、终局类型合理 |
| `node chess/tools/verify-endgames.mjs` | 残局库入库闸门（含解法线逐步复核） |
| `node chess/tools/gen-solutions.mjs <local\|stockfish\|emit\|check>` | 离线生成解法（**需要引擎的那条路要先装 Stockfish**） |

改着法生成或搜索之后，除了跑对应测试，建议再跑一次自对弈。

## 已知限制

1. **引擎是自研 JS**，棋力有上限（目标「陪人下完一盘」，不承诺对强引擎）。
2. **没有开局库**：前几步靠搜索，慢一点、变化少一点。
3. **残局库只有 25 局，其中 7 局带谱载杀线**：其余局「提示」要靠引擎现算，
   复杂局面可能给不出答案。没有在线表库。
4. **残局库的结论不是机器验证的**：25 局是手工构造的定式与构造题（每局标了 `source`），
   `verify-endgames.mjs` 只校验**局面合法性与解法线可走**，不证明胜负。
5. **AI 思考期间不能中断**：最长 1.5 秒内禁用操作，不做取消。
6. **移动端不做拖拽**：触屏走「点选 → 点目标」两步，与象棋一致。
7. **必须走 http 服务**：ES Module、Worker，以及棋子图形的 `fetch` 在 `file://` 下都不工作
   （棋子会退化成占位圆圈，状态行会写明原因）。
8. **不做 PGN 导入导出、不做棋钟、不做变例树**；不做局面编辑器
   （但可以把当前局面存成自定义局面，或粘一段 FEN 载入棋盘）。
9. **锦标赛细则不做**：三次重复 / 50 步由本模块自动判和，不需要对局者提出。
10. **自定义局面存在 localStorage**：清浏览器数据 / 换设备都会丢，最多 100 条。
