# 中国象棋（网页单机版）

浏览器里对弈中国象棋。纯静态 HTML + CSS + JS，无构建工具、无框架、无第三方依赖。
四个挡位的 AI、中文记谱、复盘跳转、悔棋重做、提示、深色模式，
外加一个**局面库**：内置 559 局残局（8 局实用残局 + 551 局《适情雅趣》），
还可以把你下到一半的局面存下来，或者粘贴外部 FEN 导进来。

**AI 有开局库了**：标准开局的头几手走的是谱上的着法，局面在库里就直接走谱、**不做搜索**（零耗时）。
库有**两半**：手写的 7 条线（中炮对屏风马、顺炮、列炮、单提马、仙人指路、飞相局、起马局），
以及 **Pikafish 离线生成的谱**（1,789 个局面 / 3,492 条候选，覆盖到第 8 个半回合），
合并后索引里 1,794 个局面。挡位越高越倾向按谱走（入门只有一半的时候按谱，高级只要库里有就一定走）；
对手不按谱走、或者库没写到那么深时，一律回退常规搜索。
**左右镜像的局面同样命中**：库只写右手那一半，你走 炮八平五 与 炮二平五，AI 按同一套谱应着。
数据格式、索引方式、生成器怎么跑、以及「为什么它和位置表是两回事」都在
[`docs/openings.md`](./docs/openings.md)。

**长将会判负**：同一局面出现三次本来判和，但如果走成循环的一方**每一步都在将军**，
按棋规**判那一方负**（双方互将则判和）。**AI 也知道这一条** —— 它既不会自己一路将军
走成循环，也会主动把对手逼进去。长捉 / 长兑 / 一将一杀仍然不做（见 [`docs/decisions.md`](./docs/decisions.md) 第 10 条）。

**局面也能拿出去**：复制 FEN 给别的软件，或者复制一条**分享链接** ——
别人点开就能直接看到这个局面、接着下。**棋谱也能拿出去** ——
「着法」面板标题右边点一下就复制成一段文本（一行一个回合）。

**残局能「按线走」**：库里 455 局带一条可以跟着走的线（离线用 Pikafish 引擎算出来、
再用本模块的规则层逐步校验过），分两种，**列表和状态行会分开措辞**：

| 徽标 | 局数 | 是什么 |
|---|---|---|
| **有解法** | 399 | 引擎在根上**证明了强制杀**（对手怎么走都杀）—— 可以放心跟着走 |
| **参考线** | 56 | 引擎沿自己选的着法**走到底能杀**，但**前段没有证明** —— 跟着走能到将死，别当正解 |

两种都是：棋盘上方标出这条线，「提示」直接给线上的着法（状态行分别写「谱载解法」/「引擎参考线（非证明）」），
**不派发搜索、省掉最长 1.5 秒的等待**。匹配方式是**把「你实际走过的着法」与棋谱逐手比**
（见 `js/solution-book.js`）：一直跟着谱走就每一步都给谱上的下一手，一旦走岔（**或者对手变了着**）
就自动回退成引擎现算。

**也可以不下 AI** —— 侧栏「对局」面板里有个**双人对弈**开关，
打开后红黑两边都由人来点（同一台设备上轮流走）。

**「AI 按谱应着」**（同一个面板，**只在当前这一局有谱时才出现**，默认关）：
关着时 AI 一律实时搜索、按挡位出着 —— 有解法的局里它是对手，会还手、会变着，
于是你多半走不完那条线；打开后 AI 严格照谱应着，你就能顺着解法一直走到将死。

棋盘上**轮到谁走，那一方的棋子就带一圈紫色高亮外圈**；
棋盘上方那行状态里的「红方 / 黑方」也跟着上色，不用去读文字就知道该谁走了。
**被将军时**状态行开头写「将军」（红字），棋盘上被将的那个将 / 帅另有一道红圈。

**战斗状态和棋谱说明就在棋盘正上方**（轮到谁走 / 将死 · 谁胜 / 当前是哪一局 · 已走几步）。
不放侧栏是有原因的：窄屏下布局是单列（棋盘 → 工具栏 → 侧栏），
放侧栏会被挤到整页最下面，正在下棋时根本看不见。

## 本地运行

用了 ES Module，**不能直接双击 `index.html`**（`file://` 下会被 CORS 拦掉），
Worker 也需要 HTTP 环境。起个静态服务即可：

```bash
cd treert.github.io
python -m http.server 8000
# 打开 http://127.0.0.1:8000/chinese-chess/
```

部署在 GitHub Pages 上是 HTTP 服务，不受影响。

## 架构

**分两层。** 对局层（`game.js`）是纯逻辑状态机，界面层只负责把它画出来、
把点击翻译成它的调用，自己不持有任何棋类规则。

**状态集中在 `main.js` 的 `app` 对象上。** 其他模块之间不互相 import，
统一通过 `app` 上的回调协作，避免依赖成网 —— 与 `conway-life-game` 同一套做法。

**AI 跑在 Worker 里。** 主线程只发 `{ fen, level }`、收着法。搜索期间主线程禁用操作
（最长 1.5 秒不可中断，见「已知限制」）。

**数据流**：点击格子 → `interaction.js` → `app.onCellClick` → `game.js` 校验并走子
→ `refresh()` → `renderer.draw()` → 若轮到 AI，`worker.postMessage` → 回来再走一步。

## 双人对弈

侧栏「对局」面板里有个**双人对弈**开关，打开后不走 AI：

- 红黑两边都由人来点，棋盘上方的状态行不再说「你 / AI」，只说「轮到红方」
- **「执子」会被禁掉** —— 双人模式下它没有意义（想让黑方在下方，用「翻转」）
- **「悔棋」只退一步**。人机模式会一直退到轮到你走，那在双人模式下会把对手刚走的那手也抹掉
- 「提示」和「挡位」照旧可用 —— 提示是给「当前走棋的人」用的，不专属某一方

开关状态跟着存档走，刷新页面不会丢。

## 常见改动

### 调整某个挡位的手感

改 `js/config.js` 的 `LEVELS`。四个参数的含义：

| 参数 | 作用 |
|------|------|
| `depth` | 迭代加深的上限，实际由 `timeLimitMs` 截断 |
| `timeLimitMs` | 时间上限（毫秒） |
| `quiescence` | 是否做静态搜索。**关掉会让 AI 明显「像新手」** |
| `noise` | 根节点评分扰动幅度。越大越容易走次优着 |
| `blunderRate` | 按此概率故意走次优着（模拟看漏）。只剩一个合法着法时不触发 |
| `book` | 查开局库的概率（0~1）。越大越倾向按谱走开局，0 = 完全不用。见 [`docs/openings.md`](./docs/openings.md) |

### 提升棋力

**评估方向**：改 `engine.js` 的 `evaluate()` 与 `config.js` 的 `PIECE_SQUARE_OPENING` /
`PIECE_SQUARE_ENDGAME` / `PHASE_WEIGHT` / `PAWN_BONUS_*`。

**先看这段再动手**：评估已经补过一项**机动性**（车 / 马 / 炮的可达格数，在 `engine.js`），
这是第一个在尺子上量出正收益的评估改动（平均损失 −4cp、漏着率 17% → 13%，
取舍与代价见 [`docs/decisions.md`](./docs/decisions.md) 第 19 条）。
**它的权重写对过一次**：2026-10-06 发现数组把**车 / 马 写反了**（马 3 / 车 2，而文档与棋理都是车更重），
修完 opening 45.9 → 43.2（漏着 3 → 2）、回归集 179.0 → 151.0，并且
**回归集第一次命中裁判首选**（0/5 → 1/5）—— 见第 22 条。

**但别顺手去微调位置表**：2026-10-06 试过给兵补一行行分（兵原来在两张表里一格都没有），
补完**一步棋都没换**（固定深度对照：×1 / ×2 都是 0/65）。原因是位置表这类
「静态形状」项**在同一个局面内近乎恒定**，对候选着法没有区分度 ——
所以「继续微调手写位置表」这条路基本可以放下，该找的是**对每个候选着法都有区别**的项。
见第 21 条。

**「威胁 / 无根子」也不行**（这是最容易想到的下一个候选）：2026-10-06 先诊断出
两条最严重的漏着**在深度 6 上是被排反的**（★ 真值差 442cp，模块认为坏着好 77cp），
差距在**静态评估这一层就全在了**；再用探针量「被攻击且没人保护」这个特征分不分得开那两步棋：
19 个两步不同的局面里它偏向裁判首选的只有 **5 个（26%）**。**结构性原因**：静态搜索
**已经把吃子序列搜干净了** —— 「谁是白送的」本来就由 `quiesce` 负责，评估里再静态扣一次
是**重复计**。见第 23 条。

**打盘数（对局级指标）验过了，不做**：2026-10-06 跟 Pikafish 下了 16 盘 ——
depth 3 是 80%（6 胜 4 和 0 负）、**depth 6 正好 50%**，所以**没饱和**（原本以为会全败）；
但每盘要 1.5~2 分钟，要分辨 5 个百分点得下 **380 盘 ≈ 10 小时**，
而且**一半的胜局来自「对方长将判负」**（弱挡位看不见循环规则，那不是棋力）。
它唯一看到而 cp 判据看不到的是「**赢棋走和**」（有 3 局撞上 200 半回合上限判和）——
所以那个缺口改用便宜的**定式转换测试**去抓，而不是打几百盘。见第 26 条。

**机动性那三个权重也正式量过，结论是「不用调」**（现状 车 3 / 马 2 / 炮 3）：
扫了 车2~4 × 马1~3 × 炮2~4 的网格，「最好」那组与现状的差别**只来自一两个局面**
（配对 2 胜 22 平 1 负），而把开局局面从 30 个提到 **120** 个之后结论就翻了 ——
**前两轮的网格根本不足以分辨这三个权重**。两条教训值得记住：

- **看总损失会被一个局面的运气骗**（「−182cp 的改进」可能就来自 1 个局面）。
  要比就比**逐局面的配对胜负**。
- **别拿 ρ（同局面排序相关）当调参目标**：它在这件事上给出**反向**结论
  （说「关掉机动性更好」，而 cp 判据说关掉**差 322cp**）—— 它适合比较同一类信息的候选
  （C1 那次），不适合给「加不加某一项」投票。见第 24 条。

**量棋力请用 [`tools/strength.mjs`](./tools/strength.mjs)**（拿 Pikafish 当裁判算平均损失 / 漏着率）——
别靠感觉，也别用「离老师的 MAE」那种判据（那是 `future-work.md` C1 踩过的坑）。

**小改动先看它换了几步棋** —— 用 [`tools/move-diff.mjs`](./tools/move-diff.mjs)：
固定深度 + 无随机性 ⇒ **完全可复现**，比的是离散量「选了哪一步」，不受时间抖动影响；
`--judge` 时再**只在不同的那几个局面上**让 Pikafish 定向判分（信噪比最高的地方）。

```bash
node chinese-chess/tools/move-diff.mjs dump --out tmp/a.json   # 1. 存一份着法快照
#   ...改代码...
node chinese-chess/tools/move-diff.mjs compare tmp/a.json --judge   # 2. 比 + 定向判分
```

**「换了 0 步」是一个结论，不是失败**：说明这个改动碰不到着法选择（静态形状类的
位置表数据经常如此），就不必再上尺子了。三把仪器跑的是**同一批局面**（取法只有一份，
在 `tools/strength-positions.mjs` 里）。

**比一组参数用 [`tools/eval-compare.mjs`](./tools/eval-compare.mjs)**：把几组参数各走一遍
（固定深度 ⇒ 完全确定），逐局面算损失并做**配对对照**；裁判评分按 `(局面, 着法)` 缓存，
所以扫一组配置很便宜。

```bash
# 机动性权重：现状 / 关掉；或者子力值（士/相/马/车/炮/兵）
node chinese-chess/tools/eval-compare.mjs --configs "mobility=3/2/3,mobility=0/0/0"
node chinese-chess/tools/eval-compare.mjs --configs "piece=200/200/400/900/450/100,piece=200/200/400/900/500/100"
```

⚠️ **准备采纳一个改动时，固定深度的结论必须在至少两个深度上复核**
（只跑了深度 6 就已经是「平局」或「明显更差」的，不必再跑第二个）；
这条是 2026-10-06 用一次「漂亮但假」的改动换来的：把炮的基础值从 450 提到 600，在**深度 6** 上是总损失 −979、配对 20 胜 7 负、
四个组全变好、扫 450~900 还是有内部最优的光滑曲线 —— 换到**深度 7 当场消失**
（同 124 个开局局面从 −457/9 胜 2 负 变成 −54/**5 胜 8 负**），真实预算的尺子也不支持，
最后**撤销**了。对照：机动性开关在两个深度上量级一致（中局 +322 → +447），才算站得住。

**这把尺子按局面集分组报**，因为「全混在一个数里」的读数骗过我们：
★那盘 430cp 的漏着只凭自己就把整组均值抬了一倍（同一个 opening 组，
单独算是 45.9、混着★算是 60.8）。四组与当前基线（真实 1.5 秒、裁判 depth 16）：

| 组 | 局面 | 现在是什么样 | 关心什么 |
|---|---|---|---|
| `opening` | 30 | 平均 45.9 / 漏着 3 | 开局阶段别犯傻 |
| `middlegame` | 20 | 平均 36.1 / 漏着 2 | 评估与深度都说了算 |
| `endgame` | 10 | 平均 7.9 / 漏着 0 | 别在残局里悄悄变坏（它**量不出提升**，最不灵敏） |
| `regression` | 5 | 平均 179.0，**命中裁判首选 0/5** | 「那几条炮的着法修好了没」 |

```bash
node chinese-chess/tools/strength.mjs              # opening + regression（默认，最快）
node chinese-chess/tools/strength.mjs --set all    # 四组全跑（65 个局面，十几分钟）
```

**回归集是逐条看的**（`✅` = 模块这一手与裁判首选一致），不是看它的平均数 ——
那五条里四条是同一个毛病（炮往前顶 / 横挪），平均一下就埋了。
局面集本身在 [`tools/strength-positions.mjs`](./tools/strength-positions.mjs)（冻结的数据，
**别手改**：想换局面得重跑采集脚本），取舍与否决项见
[`docs/decisions.md`](./docs/decisions.md) 第 20 条。

位置表已经做了**两张**（开局 / 残局），评估按相位插值 —— 见
[`docs/decisions.md`](./docs/decisions.md) 第 11、12 条。但它们都是**手写的常识版**。

**"换成 Pikafish 实测表"这条路 2026-10-05 试过了，结论是不行**：引擎的分值刻度
与模块的子力比差得远（它认的车 ≈ 690、兵 ≈ 22），位置表会被迫去替子力做补偿，解出来巨大而锯齿；
换成模块原有的「纵线分 + 行分」结构化形式、甚至把样本换成引擎对局，也都一样。
四种尝试的**同局面排序相关**都只有 0.11~0.16，而现有手写表是 **0.22~0.32**（随测的分布变）——
手写这套在真正重要的维度上每次都赢。过程与数据见
[`docs/future-work.md`](./docs/future-work.md) C1，工具留在
[`tools/gen-pst.mjs`](./tools/gen-pst.mjs)（随时可以再试）。

**不要加「机动性」这类需要生成着法的项** —— 评估在叶节点被调用上百万次，
生成着法等于把搜索成本翻倍。位置表之所以能加，是因为它是 O(1) 查表。

**开局方向**：手写那半改 `js/openings.js`（加一行 + 跑 `node chinese-chess/tools/test-openings.mjs`）；
生成那半重跑 `node chinese-chess/tools/gen-openings.mjs grow/report/emit`（要本地有 Pikafish，
深度 / 每层候选数 / 阈值怎么权衡见 [`docs/openings.md`](./docs/openings.md) 第 6 节）。

**搜索方向**：改 `LEVELS` 里的 `checkExtension`（将军延伸的层数上限）与
`mateProbePly`（连将杀探测的层数上限）。这两个是「排局连杀」从看不见到看得见的开关，
机制见 [`docs/decisions.md`](./docs/decisions.md) 第 9 条。加大它们的代价是同样的时间预算下常规搜索浅一层 ——
`config.js` 里写了怎么权衡。

**着法排序**：置换表着法 → 好/中性吃子（MVV-LVA）→ 杀手 → 历史启发 → **坏吃子**（近似 SEE）。
实现上**按需挑选**（不做整表排序）：节点数与旧写法逐位相同、时间少 1.3~1.5 倍；
坏吃子降级再省 16~19% 节点。PVS、历史启发衰减、反走着法都试过 —— 不划算或无效，默认不用。
都见 [`docs/decisions.md`](./docs/decisions.md) 第 16 条与
[`docs/future-work.md`](./docs/future-work.md) C2（那里也写明了：**1.3 倍速度 ≈ 0.15 层**，
常数因子买不来棋力）。

**合法性判定**走「与将帅不共线就直接判合法」的快路径（`decisions.md` 第 17 条），
`isAttacked` 与着法生成也按索引重写过：2026-10-06 这一轮合计 **−18% 时间** ——
高级挡位那 1.5 秒里能搜的节点从约 1.6~2.1M 涨到 2.4~2.7M，四个测试局面里有一个多搜出一层。

**不顺手的挡位**：还是改 `LEVELS` 里的 `depth` / `timeLimitMs` / `noise` / `blunderRate`。

### 加一个残局

**不想碰代码**：用页面的「保存 / 导入」把局面存成自定义局面，见 [`docs/positions.md`](./docs/positions.md)。

**想进内置库**：见 [`docs/endgames.md`](./docs/endgames.md) 的「加一局 / 改一局」——
在 `js/endgames.js` 加一条数据后，跑 `node chinese-chess/tools/solve.mjs --ids <id>` 一条命令就够。

### 改棋盘样式

颜色在 `style.css` 顶部的 `--xq-*` 变量里（深浅两套）。
棋盘的线、河界、九宫分别在 `.xq-cell::before/::after` 和 `.xq-board::before/::after` 里；
外框、楚河汉界、上下纵线号、星位直角是 `renderer.js` 建的 `.xq-deco` 一层，
位置全用 `cqw`（1 格 = 11.111cqw）；纵线号借 `.xq-board` 的上下 margin 站在棋盘外面。

## 已知限制

> 下面是一份**给使用者看的摘要**。完整的清单（含每条的改进路径与工作量估算）、
> 以及「设计里写了但没实现」「实现偏离了设计」的记录，都在
> [`docs/future-work.md`](./docs/future-work.md)。

| 限制 | 说明 |
|------|------|
| **循环规则只做长将** | 长将判负已实现（规则层定性 + AI 侧同步，见 [`docs/decisions.md`](./docs/decisions.md) 第 10 条）。长捉 / 长兑 / 一将一杀仍然不做 |
| **重复判定在搜索里提前一次** | 引擎按「局面第 2 次出现」就当作循环成立（棋规要第 3 次）。这是引擎里的标准近似：能原样回来一次就能一直回来 |
| **评估是「子力 + 手写位置表（开局 / 残局两张，按相位插值）」** | 两张表都是「纵线分 + 行分」的手写版（常识级：中路、过河、出子、帅不乱动 / 残局马更强、炮缺炮架、老将出马…），不是从强引擎换算的实测表。相位权重也是手写的。高级挡位大约业余中低水平（连杀例外 —— 那是搜出来的，不是评出来的） |
| **开局库到第 8 个半回合为止** | 两半数据：手写 **7 条线 / 25 个局面** + Pikafish 生成的谱 **1,789 个局面 / 3,492 条候选**（合并后索引 1,794 个局面），**左右镜像归一**（只写右手那一半，走左炮也命中）。库外的局面一律回退常规搜索 —— 注意**谱里只有引擎认为可走的着法，对手走一步次优着就掉出谱**，所以它治的是「开局不像人」，不是棋力。详见 [`docs/openings.md`](./docs/openings.md) |
| **弱挡位看不见一步杀** | 入门 / 初级两个开关都没开（将军延伸、静态搜索），`depth <= 0` 的节点不生成着法，所以看不见。中级 / 高级两个都开着，能看见 |
| **连杀探测只证明「有杀」** | 本地引擎的探测把攻击方限制在将军着法上，所以「找不到」不等于「没有」。**有谱载解法的局不受这条影响**（那是引擎证明过的杀线）；没解法的局仍可能给出错的提示 |
| **AI 思考期间不能中断** | 最长 1.5 秒内禁用操作，不做取消 |
| **走子动画只覆盖「刚走一步」** | 悔棋 / 复盘跳转是全量重绘，没有补间 |
| **棋子字形依赖系统楷体** | 字体栈 `KaiTi → STKaiti → SimSun → serif`，缺楷体的系统会兜底成衬线体 |
| **移动端不做拖拽** | 触屏走「点选 → 点棋盘」两步，避免与滚动打架 |
| **必须走 http 服务** | ES Module 与 Worker 在 `file://` 下都不工作 |
| **残局库的结论与「线」都不保证** | 559 局的胜负结论**没有一条经过机器验证**（实用残局取教材定式；适情雅趣卷六逐局核对过通行整理本，改了 29 局）；455 局带可以跟着走的线（399 局是已证明的杀线 + 56 局**引擎参考线**，后者走到底能杀但前段没有证明、**不是正解**）；剩下 104 局没有线，只能靠本地引擎现算、可能给不出答案。详见 [`docs/endgames.md`](./docs/endgames.md) |
| **不做局面编辑器** | 不能自由摆棋。但可以把**当前局面**存成自定义局面，或者粘一段 FEN —— 收进库里，或者直接载入棋盘 |
| **自定义局面的边界** | 不做「达成目标」判定（程序无从知道你存那个局面时的胜负，想要结论得进内置库）；存在 localStorage，清浏览器数据 / 换设备 / 换浏览器都会丢，最多 100 条。详见 [`docs/positions.md`](./docs/positions.md) |

## 残局库

内置 559 局，分成四页（两种「线」的徽标与含义见开头）：

| 分类 | 局数 | 说明 |
|------|------|------|
| 实用残局 | 8 | 教材定式（单车例胜单士、单车难胜士象全、马擒单士…）。结果可靠，适合入门训练 |
| 适情雅趣·杀局 | 467 | 《适情雅趣》第一至五卷的连杀排局，**全谱一条不漏**（FEN 一个字符都没改）。多为十几步的连杀，适合欣赏 |
| 适情雅趣·和局 | 84 | 卷六的实用残局与和局研究：红先和 79 局、红先胜 3 局、黑胜 2 局。练守和用 |
| 自定义 | 0 起 | 你自己存下来的局面，见 [`docs/positions.md`](./docs/positions.md) |

**这里的结论没有一条是机器验证过的**，两种「线」的可信度也不一样 ——
数据来源与授权、逐局核对的过程（卷六改了 29 局）、局号比通行本大 1 的原因、
`result` 字段的可靠性边界、解法与参考线怎么生成的、以及**加一局 / 改一局**的完整流程，
都在 [`docs/endgames.md`](./docs/endgames.md)。

## 自定义局面

局面库弹窗里有个 **「自定义」页签**，放你自己存的局面：「保存 / 导入」把局面收进库、
把粘来的 FEN 摆到棋盘上（**临时局面**，不进库）、把当前局面复制成 FEN / 分享链接 / 着法拿出去。

**三处入口的分工、两道校验的松紧、临时局面的行为、存储位置与上限**，
都在 [`docs/positions.md`](./docs/positions.md)。
