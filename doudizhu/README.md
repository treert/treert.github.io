# 斗地主（网页单机版）

浏览器里和两个 AI 打斗地主。纯静态 HTML + CSS + JS，**无构建工具、无框架、无第三方依赖**。

**1 个真人 + 2 个 AI**，四个挡位，叫分、春天、炸弹翻倍都做了。
**刷新页面不会丢局** —— 重新打开接着打。

**最要紧的一条：AI 看不到别人的手牌。** 这不是一句君子协定，是架构上的约束，
而且有一条**可执行的测试**在守它（造两份"公开信息相同、隐藏信息不同"的对局，
断言 AI 的决策逐字节一致）。连"猜牌"用的那批"可能的世界"也是从**公开信息**推出来的。

## 本地运行

用了 ES Module 和 Worker，**不能直接双击 `index.html`**（`file://` 下会被 CORS 拦掉）：

```bash
cd treert.github.io
python -m http.server 8000
# 打开 http://127.0.0.1:8000/doudizhu/
```

部署在 GitHub Pages 上是 HTTP 服务，不受影响。

## 玩法速览

- 点手牌选中（可多选），点「**出牌**」。压不过上一手时按钮会给原因，不弹窗。
- 「**提示**」按当前能出的所有牌型从好到坏循环给出，并自动帮你选中对应的牌。
- 「**记牌器**」显示**还没出现过的牌**（54 张 − 我的手牌 − 已经打出去的）——
  这是任何只看牌面的观众都能算出来的信息。它**不会**告诉你对手手里有什么。
- 「**托管叫分**」交给当前挡位的 AI 代叫 —— 不会叫分的时候用。
- 键盘：<kbd>←</kbd><kbd>→</kbd> 移动焦点，<kbd>空格</kbd> 切换选中，
  <kbd>Enter</kbd> 出牌，<kbd>P</kbd> 不要，<kbd>H</kbd> 提示，<kbd>Esc</kbd> 清空。

│   │   ├── sample.js          采样：view → 一个"可能的世界"

**`js/` 下除 `worker.js` 外全是纯逻辑**（不出现 `document` / `window` / `localStorage`），
所以能在 Node 里被 `tools/*.mjs` 直接加载测试，也能被 Worker 加载。

## 架构

**分三层，每层都能单独测：**

```
规则层   cards / combo / moves        纯函数，只有它知道自己"错了"
状态层   game / view / persist        状态机 + 视角隔离 + 存档
AI 层    evaluate / ai/*              只吃 view，看不到 game
界面层   renderer / interaction / main 不持有任何牌类规则
```

- **状态集中在 `main.js` 的 `app` 上。** 其他模块之间不互相 import，
  统一通过 `app` 上的回调协作，避免依赖成网（与象棋、conway 同一套做法）。
- **AI 跑在 Worker 里。** 主线程只发 `{ view, levelId, seed }`。
  这也让"AI 拿不到对局状态"成了**物理事实**，而不只是约定。
- **`view` 是隐藏信息的唯一闸门。** `game.hands` 里三家手牌都有，
  但 AI 与界面拿到的都是 `viewOf(game, seat)` 过滤过的产物：
  只有我自己的牌面 + 公开信息（张数、已出的牌、已翻开的底牌）。

## 关键设计决策

完整版（含否决了什么）在 [`docs/design.md`](./docs/design.md)，这里挑最有特色的几条。

### 1. 「不偷看」是一个**可以执行的测试**

`tools/test-ai.mjs` 的 (a) 段：造两份**公开信息相同、隐藏信息完全不同**的对局
（把另外两家的牌合起来重新洗一遍再按原张数分回去），然后断言
**① 两个 `viewOf` 完全相同，② `decide` 的决策也完全相同**（四个挡位都跑）。

第 ② 条在 `decide` 是纯函数的前提下是自动成立的 —— 它真正防的是
**AI 里藏了模块级可变状态**；第 ① 条才是正面证明：view 不随隐藏信息变化。

判据很清楚：**能从"只看公开牌面的观众视角"推出来的信息，就不是泄漏。**
所以采样器（`sample.js`）用"还没出现过的牌"是合法的，而农民之间的"配合"
只能靠公开信息（谁出的、什么角色、还剩几张），不能去读队友的手牌。

### 2. `combo` 是「这组牌的一种解释」，不是「这组牌的类型」

同一个 `cards` 可能对应多个 combo。`333444555666` 既是四连飞机，也是
三连飞机带 `666`，还是三连飞机带 `333`；`33334444` 既是飞机带单也是四带两对。

所以识别函数是 `identifyAll(cards) -> combo[]`，判"能不能出"是
`canBeat = identifyAll(cards).some(c => beats(c, last))`。

**单值版本会犯一个具体的错**：手里 `444555666777`，场上 `飞机带单（主体 345）`，
按"飞机优先"读成四连飞机 → 类型不匹配 → 告你"压不过"，但其实可以当
`飞机带单（主体 456）` 出。**「我明明能出、程序说不能」是扑克程序里最坏的一类错。**

`tools/test-combo.mjs` 里那两条用例就钉着这件事，改回单值它们会立刻变红。

### 3. 弱化参数**不是线性叠加的**，它们会互相抵消

四个挡位的参数是拿 `tools/selfplay.mjs ab` 对照量出来的（固定座位 0 当地主，
只改两边挡位，看"地主胜率"这**一个**数）。两个反直觉的实测结论：

| 现象 | 数据 |
|------|------|
| **「深而窄」的搜索比「浅而宽」差** | `depth 2 / width 3` 当农民 : 地主胜率 40.2%；`depth 1 / width 4` : **33.1%** |
| **噪声会把 PIMC 的收益整个吃掉** | 中级原本 `noise 20 / blunderRate 0.03`，农民强度**和无 PIMC 的贪心基线没区别**（52.8% vs 53.3%）；降到 `8 / 0.01` 之后才落到 44.8% |

第一条的原因：`innerWidth: 3` 等于假设"对手只有 3 种应手"，深度越深越自信 ——
**它不是"深度不够"，是模型不对。**
第二条的原因："给弱挡位加噪声"和"给弱挡位加算力"是方向相反的两件事。

### 4. 搜索的时间预算用「用尽就停止加深」，不抛异常

异常会从 `make` / `unmake` 中间穿过去，把搜索状态留在"走了一半"的样子。
象棋的引擎在同一个坑里摔过（见 `../chinese-chess/docs/design.md` §7.1）。
这里改成"预算用尽就当作叶子"——安全，而且只是精度下降。

### 5. 存档：**整份丢弃**，且恢复时校验 54 张守恒

读不出来 / 版本不对 / 校验不过 → 一律开新局，不阻塞启动。
校验里最重要的一条是**54 张守恒 + 无重复**：它挡住的是"手牌张数写对了但内容对不上"
那种半坏不坏的状态 —— 那种状态进了游戏不会立刻报错，
只会在几十手之后以一个完全无关的症状炸出来。

（这和「自定义局面列表」的逐条校验**正好相反**：那边是"一个列表"，
丢一条好过丢全部；这边是"一个对局"，半个对局比没有更难查。）

## 常见改动

### 调某个挡位的手感

改 `js/config.js` 的 `LEVELS`。九个参数的含义见 `docs/design.md` §7.5。
**改完请跑一次对照**，不要凭感觉调：

```bash
node doudizhu/tools/selfplay.mjs ab hard medium 600   # 地主高级 vs 农民中级
node doudizhu/tools/selfplay.mjs 500 hard             # 同挡位自对弈（看流局率与耗时）
```

`ab` 模式会把两边用到的**完整参数**打出来 —— 这是为了让"参数确实不同"一眼可验。

### 加/改一个牌型

1. 在 `js/combo.js` 的 `identifyAll` 里加一段判定（**按类型逐个试**，不要按张数 switch）
2. 在 `js/moves.js` 的 `enumerateCombos` 里加对应的枚举
3. 跑 `node doudizhu/tools/test-combo.mjs` 与 `test-moves.mjs`

`test-moves.mjs` 会用**暴力法**核对（枚举手牌的全部子集，按 §5.3 的集合定义过滤），
所以"漏枚举"这件事一定会被抓到。

### 改界面

- 手牌宽度、重叠间距：`style.css` 里 `.ddz-hand` 的 `--ddz-step`（JS 会按容器宽度算）
- 牌的颜色：`style.css` 顶部的 `--ddz-*`（深浅两套）
- **改完 `main.js` 之后必须手动点一次「提示」和「出牌」** ——
  那是唯一一个没有静态检查能兜住的接线层（见 `docs/future-work.md` E5）

## 工具与测试

全部用 Node 直接跑，不需要浏览器、不需要装依赖：

| 命令 | 作用 |
|------|------|
| `node doudizhu/tools/test-cards.mjs` | 牌编码与发牌不变量 |
| `node doudizhu/tools/test-shuffle.mjs` | **洗牌的随机性检验**（χ²、联合分布、PRNG 质量、种子覆盖） |
| `node doudizhu/tools/test-combo.mjs` | 牌型识别与比较（含多解释的守门断言） |
| `node doudizhu/tools/test-moves.mjs` | 合法出牌生成（含暴力法核对） |
| `node doudizhu/tools/test-game.mjs` | 对局状态机（含 200 局随机对局的守恒检查） |
| `node doudizhu/tools/test-persist.mjs` | 存档校验与容错 |
| `node doudizhu/tools/test-ai.mjs` | AI 层：**不含偷看**、只出合法牌、可复现 |
| `node doudizhu/tools/selfplay.mjs [局数] [挡位]` | 同挡位自对弈冒烟 + 叫分阈值校准 |
| `node doudizhu/tools/selfplay.mjs ab [地主挡位] [农民挡位] [局数]` | **强度对照**（`greedy` 是关掉 PIMC 的基线） |
| `node doudizhu/tools/diag-ai.mjs` | **AI 内部诊断**：PIMC 有没有真的在采样、各开关接上没有 |

合计约 **14 万条断言**，但绝大多数来自**随机不变量检查**而不是手写用例：
「不偷看」180 个局面 × 4 个挡位、暴力法核对 186 个局面、
200 局随机对局每一步都查守恒。**手写用例只钉得住你想到的情况，不变量钉得住你没想到的**
—— 开发期间抓到的几个设计文档错误（见 `docs/future-work.md` 的 B 节）都是这么来的。

`selfplay.mjs` 支持 `DDZ_TRACE=1` 打印逐手日志，排查"AI 为什么这么走"时最直接。

## 已知限制

完整清单（含每条的原因与改进路径）在 [`docs/future-work.md`](./docs/future-work.md)。摘要：

| 限制 | 说明 |
|------|------|
| **刷新会丢掉"正在进行的一局"里的操作？** | 不，会**保留**。存档是整局存下来的，刷新后接着打 |
| **AI 强度有限** | 只到"会算牌、会配合"的普通人水平。搜索是**近似**（每个节点只展开前几个着法），没有置换表、没有迭代加深 |
| **不做悔棋** | 技术上不泄漏信息，但 PIMC 每次重新随机采样，"悔一步重出"会让 AI 的反应前后不一致，看起来像针对你 |
| **不能联网、不能热座** | 静态站点没有后端；扑克有隐藏信息，同屏热座不成立 |
| **没有积分/排行榜** | 只记累计局数、胜局、最高倍数 |
| **必须走 http 服务** | ES Module 与 Worker 在 `file://` 下都不工作 |
| **存档是明文** | 打开 devtools 能看到 AI 的手牌。**不做防护** —— 本模块没有排行榜也没有积分，作弊没有收益 |
| **洗牌用的不是密码学随机源** | 算法是无偏的 Fisher-Yates（`test-shuffle.mjs` 量过），但随机数来自 `mulberry32` + `Math.random()` 给的 31 位种子。够玩，但**不要**拿去当抽奖/发牌的可信来源。详见 `docs/design.md` §8.2 |
| **四个挡位的强度区间比象棋窄** | 象棋从"看不见一步杀"到"看见十三层连杀"；这里从"乱出牌"到"会配合会算牌"，跨度小得多 |
